# ValScanner v0.2.3 — Release Notes

**Release date:** 2026-05-29
**Status:** Patch release

---

## Overview

This release adds an interactive configuration wizard (`valscanner --configure`) that walks you through database-backend setup and lets you save your own defaults for every scan flag, so you no longer have to retype the same options on each run. It also significantly widens thumbnail format coverage — **HEIC/HEIF** (iPhone photos), **AVIF**, and **SVG** are now supported through the `[rich]` extra — and gives database transfers a live per-stage progress bar.

---

## User-visible changes

- **Interactive configuration wizard — `valscanner --configure`.** A new guided flow selects your database backend (SQLite or PostgreSQL), tests the connection before saving, and writes the result to `settings.json` (the PostgreSQL password goes to your OS keyring when one is available). The wizard also lets you persist default values for the scan flags — `--workers`, `--thumb-size`, the `--skip-*` toggles, logging options, and more — so those become your new defaults on every subsequent run. Saved defaults are still overridable per-invocation by passing the flag explicitly.
- **HEIC/HEIF and AVIF thumbnails.** The `[rich]` extra now bundles `pillow-heif` and `pillow-avif-plugin`, which register with Pillow automatically so HEIC/HEIF (iPhone photos) and AVIF images get thumbnails with no extra configuration.
- **SVG thumbnails.** Vector `.svg` files are now rendered to thumbnails via `svglib` + `rlPyCairo` (bundled in `[rich]`).
- **More reliable video thumbnails.** The extractor seeks 1 s into a clip for the thumbnail frame and now falls back to the first frame when that fails, so very short clips (e.g. sub-second `.3gp` voicemails) still get a thumbnail. Files ffmpeg genuinely cannot decode are left without one, with an `[thumb_video]` log line explaining why.
- **Per-stage progress bar for database transfers.** `--dump-to-sqlite` and `--load-from-sqlite` now show a live, throttled progress bar with a running rate and ETA for each stage, instead of only printing stage summaries.

---

## Upgrade notes

- **No database migration is required.**
- **No settings migration is required.** Existing `settings.json` files are read as-is; running `--configure` is entirely optional.
- **New optional dependencies in `[rich]`.** To pick up HEIC/AVIF/SVG thumbnail support, reinstall the extra: `pip install --upgrade "valscanner[rich]"`. On macOS and Windows the new wheels ship their native codecs. On Linux they may build from source — install the system libraries first: `apt-get install libheif-dev libavif-dev libcairo2-dev` (Debian/Ubuntu) or `dnf install libheif-devel libavif-devel cairo-devel` (Fedora/RHEL).

---

## Fixes

- Video thumbnail extraction no longer skips very short clips: it now falls back to the first frame when seeking to 1 s yields no frame.
- 3D/CAD model extensions (`.obj`, `.stl`, `.blend`, `.fbx`, `.gltf`, `.glb`, `.dwg`, `.dxf`, and others) are now categorized as `other` rather than being mistaken for images and sent through the image thumbnailer.

---

## Internal

- `valscanner/config_wizard.py` — new module implementing `run_wizard()`, invoked by `valscanner --configure`.
- `valscanner/core/app_settings.py` — adds `cli_defaults()` / `save_cli_defaults()` and the `CLI_DEFAULTS_BUILTIN` table; CLI argument defaults now resolve through saved config.
- `valscanner/_telemetry.py` — Sentry now samples error events at 0.1% (`sample_rate=0.001`) to cap event volume in production.
- CI installs cairo development libraries on Linux so `svglib`/`rlPyCairo` rendering works in the test and build workflows.

---

## Upgrading

```bash
pip install --upgrade valscanner
```

If you use the rich output or web UI:

```bash
pip install --upgrade "valscanner[rich]"
pip install --upgrade "valscanner[web]"
```
