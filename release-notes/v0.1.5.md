# ValScanner v0.1.5 — Release Notes

**Release date:** 2026-05-20  
**Status:** Incremental release

---

## Overview

v0.1.5 is a database-layer release. The entire persistence stack has been rewritten on top of **SQLAlchemy**, with a new **repository layer**, **Alembic migrations**, and **multi-backend support** (SQLite + PostgreSQL). The GUI gains a Database Settings dialog that lets you pick a backend and connect asynchronously, and the schema now auto-bootstraps and auto-migrates on first connect. Byte columns are widened to `BIGINT` so scans larger than 2 GiB total size no longer overflow.

---

## New Features

### SQLAlchemy persistence layer

`valscanner/core/schema.py` has been rewritten using SQLAlchemy tables and column types. All previous raw-`sqlite3` callers — scanner, exporter, similarity engine, GUI models and panels, GUI workers, the CLI, and every web router — now talk to the database through SQLAlchemy sessions.

A new **repository layer** in `valscanner/core/repository/` provides typed accessors:

| Module | Purpose |
|--------|---------|
| `scans.py` | Scan session CRUD |
| `files.py` | File rows + bulk insert |
| `folders.py` | Folder totals |
| `media.py` | Thumbnails + media samples |
| `search.py` | Full-text and filter queries |
| `analysis.py` | Folder-similarity inputs |

The old `valscanner/core/db.py` becomes a thin facade kept for backwards compatibility.

### Multi-backend support (SQLite + PostgreSQL)

Three new modules drive backend selection and configuration:

- **`core/app_settings.py`** — persisted app preferences (current backend, last-used URL, recent connections).
- **`core/db_config.py`** — URL parsing, dialect detection, engine factory.
- **`core/exceptions.py`** — typed errors (`DatabaseConfigError`, `SchemaError`, …) so the UI can surface friendly messages.

PostgreSQL gets its own FTS implementation (migration `0003_pg_fts`) using a `tsvector` column and `GIN` index, mirroring the SQLite FTS5 functionality.

### Alembic migrations

ValScanner now ships **Alembic** for schema versioning. Five migrations are included in this release:

| Revision | Description |
|---------|-------------|
| `0001_baseline_schema` | Initial table set |
| `0002_add_filters_json` | Persisted scan filters as JSON |
| `0003_pg_fts` | PostgreSQL full-text search column + GIN index |
| `0004_indexes` | Performance indexes on hot lookup paths |
| `0005_bigint_byte_columns` | Widen `size_bytes` / `total_bytes` to `BIGINT` |

Migration files live in `valscanner/migrations/versions/` and are packaged with the wheel.

### `bootstrap.ensure_schema`

A new `valscanner/core/bootstrap.py` exposes `ensure_schema(engine)` which:
- creates the database if it doesn't exist,
- runs any pending Alembic migrations,
- and stamps fresh databases at the latest revision so new installs don't run the full migration chain unnecessarily.

`ensure_schema` is called automatically by the CLI, the GUI's `ConnectWorker`, and the web server on startup — you no longer have to think about schema setup.

### Database Settings dialog (GUI)

The desktop app now includes a **`DatabaseSettingsDialog`** (`valscanner/gui/dialogs.py`) for picking a backend, entering a URL, and saving the choice to app settings. Connections happen in a new **`ConnectWorker`** background thread with the matching async `_load_url` path in `window.py`, so the main window stays responsive while a remote Postgres connection is being established.

### BIGINT byte columns

`size_bytes` (in `files`) and `total_bytes` (in `folders`) are now `BIGINT` on every backend. Previously these were 32-bit on SQLite, which overflowed for individual files >2 GiB or folder totals >2 GiB. Migration `0005` widens both columns in place on existing databases.

## Upgrading

Existing databases will be migrated automatically on first connect — no manual steps required. If you want to inspect or run migrations explicitly:

```bash
# from the repo root
alembic -c valscanner/alembic.ini current
alembic -c valscanner/alembic.ini upgrade head
```

To use the PostgreSQL backend, install SQLAlchemy's Postgres extra and point ValScanner at your database via the Database Settings dialog or `--db postgresql+psycopg://user:pass@host/dbname`.
