# ValScanner v0.2.1 — Release Notes

**Release date:** 2026-05-28
**Status:** Patch release

---

## Overview

This release introduces **phased scanning**: each scan is now broken into five named phases (`enumerate`, `metadata`, `thumbnails`, `hash`, `samples`) that can be run independently against an existing scan. Long-running enrichment work (hashing, thumbnail generation, media sampling) can now be deferred, resumed, or retried without re-walking the directory tree, and a new `--scan-status` view shows exactly how much of each phase is done — with an optional per-extension breakdown for spotting misclassified files.

---

## User-visible changes

- **Phased scanning (CLI):** new `--phases LIST` flag accepts any comma-separated subset of `enumerate, metadata, thumbnails, hash, samples`. The default is still all five phases for a fresh scan, but you can now run, for example, `--phases hash,thumbnails` on an existing scan to fill in only those columns.
- **Re-enter an existing scan with `--scan-id N`:** when combined with `--phases` (and `enumerate` omitted), the path argument becomes optional — useful for adding hashes or thumbnails to a previously enumerated tree without re-walking it.
- **Per-phase status with `--scan-status --scan-id N`:** prints a small table showing eligible vs. done counts (and percentage) for each phase. Pass `--by-ext` to break each phase down by file extension, sorted by the number of missing items (with `--by-ext-limit` controlling the row cap, default 15).
- **Better ffmpeg diagnostics:** thumbnail and media-sample failures from `ffmpeg` now log the return code and the tail of stderr, instead of silently swallowing the error — making it much easier to see why a particular video failed to thumbnail or sample.

---

## Upgrade notes

- **No database migration is required.** Phase eligibility is computed from existing columns (`category`, `extension`, `extra_meta`, `sha256`) and the existing `thumbnails` / `media_samples` tables; older scans created on v0.2.0 work with the new `--phases` / `--scan-status` flags out of the box.
- **Default behavior is unchanged.** Running `valscanner /path/to/scan` without `--phases` still performs a full scan with all five phases enabled.

---

## Internal

- **Scanner refactor:** the per-file work for metadata extraction, thumbnail generation, hashing, and media sampling was split into small pure helpers (`_extract_metadata_for_file`, `_make_thumbnail`, `_make_sample`) driven by a shared bounded-window thread pool (`_run_pool`). Per-phase work is now uniform: submit, drain in FIFO order, commit on the main thread, with per-item timeout and cancellation honored at the same chokepoint.
- **Repository — per-phase queries:** new `FilesMixin` methods (`iter_files_missing_metadata`, `iter_files_missing_thumbnails`, `iter_files_missing_hash`, `iter_files_missing_samples`) stream candidate rows via `yield_per` to keep memory bounded on very large scans, plus `phase_status` and `phase_status_by_extension` for the new CLI report.
- **Tests:** new `tests/core/test_scanner_phases.py` exercises the phased-scan paths end-to-end (eligibility filters, re-entry via `--scan-id`, status reporting, and the by-extension breakdown).
- **Tooling guidance:** `CLAUDE.md` now documents the project-local `./tmp/` policy for throwaway fixtures and smoke-test artifacts (instead of system `/tmp/`).

## Upgrading

```bash
pip install --upgrade valscanner
```

```bash
pip install --upgrade "valscanner[rich]"
pip install --upgrade "valscanner[web]"
```
