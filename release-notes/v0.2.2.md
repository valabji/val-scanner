# ValScanner v0.2.2 — Release Notes

**Release date:** 2026-05-28
**Status:** Patch release

---

## Overview

This release fixes a long-standing bug where the GUI would fail to connect to large existing databases — the connect-time probe ran an expensive aggregation that exceeded the 10 s timeout on real-world data, surfacing as a misleading "Connection timed out" / "Connection refused" message. It also wires production error reporting (Sentry) into the GUI, CLI, and web entry points.

---

## User-visible changes

- **GUI now connects reliably to large databases.** The connect-time probe used to call an internal `summary()` helper that pulled every `tags` row from `files` into memory and aggregated them in Python — fine on a fresh DB, but easily over the 10 s ConnectWorker timeout on a populated database (PostgreSQL or SQLite). The probe is now a cheap `SELECT 1` against the configured engine; panels load their own data lazily after connect, as before. If you previously hit a "Connection timed out after 10 s" or "Connection refused" message in the status bar after upgrading, this release should resolve it.
- **Production error reporting (opt-out).** The GUI, CLI, and web server now initialize Sentry on startup so crashes can be diagnosed without asking users for tracebacks. Telemetry is **off** if `VALSCANNER_DISABLE_TELEMETRY=1` is set in the environment, and no scan content, file paths, or DB URLs are forwarded — only Python exception types, messages, and stack frames from the `valscanner` package.

---

## Upgrade notes

- **No database migration is required.**
- **No settings migration is required.**
- **Opting out of telemetry:** export `VALSCANNER_DISABLE_TELEMETRY=1` in your shell profile (or your systemd unit / launchd plist) before launching `valscanner`, `valscanner-gui`, or `valscanner-web`.

---

## Fixes

- Fixed: GUI auto-connect and the "Test connection" button in DB Settings would fail with "Connection timed out after 10 s" on PostgreSQL databases that had been in regular use, even though the same URL worked from the CLI. Root cause was the connect-time call to `Repository.summary()` performing a full-table tag aggregation in Python; the connect probe no longer does this work.

---

## Internal

- `valscanner/gui/workers.py` — `ConnectWorker` now uses a `SELECT 1` probe via `get_engine()` instead of `repo.summary()`. The `connected` signal payload is reduced to `{"url": str}`; the previously-unused `"summary"` key is gone.
- `valscanner/_telemetry.py` — new module exposing `init_sentry(component)`, invoked from `valscanner-gui`, `valscanner` (CLI), and `valscanner-web` at startup.
- `tests/conftest.py` — sets `VALSCANNER_DISABLE_TELEMETRY=1` at import time so `pytest` runs (locally and in CI) never dispatch events to the production Sentry project.

## Upgrading

```bash
pip install --upgrade valscanner
```

If you use the rich output or web UI:

```bash
pip install --upgrade "valscanner[rich]"
pip install --upgrade "valscanner[web]"
```
